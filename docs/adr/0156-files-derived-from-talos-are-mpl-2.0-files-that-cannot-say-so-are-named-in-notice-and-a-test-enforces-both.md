# 0156. Files derived from Talos are MPL-2.0, files that cannot say so are named in NOTICE, and a test enforces both

Status: Accepted · Date: 2026-11-13 · Design section: Trust · Touches: 0003, 0150

Decided: a Go file that contains Talos-derived content carries the MPL-2.0 header and no Apache block; a generated manifest or reference page that holds the same content is named in `NOTICE`, which also says where the covered source is obtained; the Talos-derived deepcopy is emitted into the MPL-2.0 union file so no Ichor-only file changes licence; and a test fails when a file does not have the treatment its kind takes.

## Context

Ichor is Apache-2.0. The Talos machinery module is MPL-2.0 with a per-file notice. Ichor generates Go types, a CRD union and CRD schemas from it, so some of its own files hold Talos's kind strings, type names, field names and documentation text. Such a file is a Modification under MPL-2.0 section 1.10(b), and the licence applies to that file; the Larger Work stays under Apache-2.0 (section 3.3). Releases distribute Executable Form, so section 3.2 obliges the distributor to say where the source of the covered files is available.

## Decision

1. **One licence per file.** A Go file with Talos-derived content carries the MPL-2.0 Exhibit A header and `// Copyright 2026 maeshinshin.`, and no Apache block. These are the four files the mirror generator writes: `pkg/typedconfig/zz_generated.{mirror,conversion,deepcopy}.go` and `api/v1alpha1/zz_generated.talosconfigpatchdocument.go`. The generator emits the header; a hand edit is overwritten.
2. **A generated manifest or page takes no header.** The Talos CRDs (`TalosCluster`, `TalosConfigPatch`), their copies in the Helm chart, the install manifest that embeds them and the reference pages that publish them hold the same content, but a header in generated YAML is overwritten by generation and is not part of a Kubernetes manifest. `NOTICE` names them as schema derived from Talos machinery and covered by MPL-2.0.
3. **The Talos-derived deepcopy lives in the MPL file.** The deepcopy methods of `TalosConfigPatchDocument` name every shipped Talos mirror type and field. The API generator gives every file of a package one header, so `api/v1alpha1/zz_generated.deepcopy.go` stays Apache-2.0 and names no Talos type: the mirror generator writes `TalosConfigPatchDocument`'s `DeepCopyInto` and `DeepCopy` into the MPL-2.0 union file, and the type is excluded from the API generator's deepcopy. No Ichor-only file changes licence.
4. **Hand-written code stays Apache-2.0.** The generator's classification tables, the field metadata and the renderers name Talos kinds and fields as lookup keys in Ichor's own data. They are not Talos-derived content and carry the Apache header.
5. **`NOTICE` is the source offer.** It travels in every release archive, every image and the Helm chart. It states that the MPL-2.0 covered files are available in source form at the Ichor repository, at the Git tag matching the artifact's version. A new covered file is added to `NOTICE` in the change that creates it.
6. **A test enforces the rule.** `internal/tools/noticecheck` fails when a generated Go file that holds Talos-derived content lacks the MPL-2.0 header or carries an Apache block, when a manifest or reference page that holds the generated Talos schema is not named in `NOTICE`, when `NOTICE` names a path that does not exist, when any Go file's header grants both licences, and when a Go file with no Talos-derived content carries an MPL-2.0 header. A Go file counts as Talos-derived when it is generated and is written by the mirror generator, lives in `pkg/typedconfig`, or imports `pkg/typedconfig` or a Talos machinery package. A manifest or page counts as Talos-derived when it holds the `Talos: <Type> — <url>` description lines the CRD generator writes. What the test cannot see is a generated file that names Talos types without importing either package, and the install manifest, which is built and not tracked; those remain a matter for review.
7. **Embedded data is listed with the third-party components.** The Sigstore public-good trusted root embedded in the controller is Apache-2.0 data from the Sigstore root-signing repository and appears in `THIRD-PARTY-NOTICES` beside the embedded Cilium chart. The older Cilium chart kept under `pkg/cni/cilium/chart` is used by tests and is neither embedded nor shipped, so it is not listed.
8. **Copyleft is refused.** `THIRD-PARTY-NOTICES` is not written when a dependency's licence text is GPL, LGPL, AGPL, SSPL or BUSL; the error names the dependency and the licence. MPL-2.0 is allowed, per file. Taking a copyleft dependency needs an ADR first.

## Consequences

A recipient of a binary, an image or the chart can find the covered source. The set of covered files is explicit and checked, and a new generated file that inherits the Apache header while holding Talos names fails the test instead of shipping. The licence boundary is a property of the generators, so a change to either generator keeps the two deepcopy files apart or the test fails. The CRD YAML itself stays unlabelled; that is a known limit of generated manifests, and `NOTICE` is where it is recorded.
