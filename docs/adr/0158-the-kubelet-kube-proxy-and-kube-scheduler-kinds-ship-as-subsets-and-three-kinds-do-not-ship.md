# 0158. The kubelet, kube-proxy and kube-scheduler kinds ship as subsets, and the kinds that do not ship are named in the decision

Status: Accepted · Date: 2026-11-13 · Amended · Design section: Typed configuration · Amends: 0155, 0157

Decided: `KubeletConfig`, `KubeProxyConfig` and `KubeSchedulerConfig` are added to the union (fields `kubeletConfig`, `kubeProxyConfig`, `kubeSchedulerConfig`). Each carries its `config` payload as a local subset of the upstream Kubernetes configuration type: the fields an operator is documented to set on a Talos node, with every field left out named in a table and refused when a Talos document sets it. `KubeAuthenticationConfig` is reclassified as Ichor-owned, `KubeAdmissionControlConfig` as unstructured, and `KubeStaticPodConfig` is in the union with its pod carried as the core v1 `Pod` without its `status`, its CRDs applied with server-side apply. Of 65 accepted kinds, all 65 are in the union.

## Context

ADR 0155 held back nine kinds whose payload is a free-form field, ADR 0157 shipped three of them, and six remained. The upstream types of the kubelet, kube-proxy and kube-scheduler configuration cannot be written as a CRD schema whole: they contain floating point numbers, a quantity type with no schema, a duration type with an untagged field, and (in the scheduler) a list with no list type. The scheduler type is also large. A kind that accepted such a document and dropped its payload would be worse than no kind, because the author would believe the setting applied.

## Decisions

1. **The subset is what an operator sets, not what a schema tool can express.** Picking by what a tool can express would choose the shape by a tooling limit and could leave out the one field anyone wanted. A field is carried when Talos's or the component's own documentation has an operator set it on a Talos node, and the generator carries every field of the upstream type that no row of the omit table names. The table (`omits` on the field override) is where each omission is recorded, with one of four reasons: Talos refuses the field in a kubelet configuration, the field's type has no CRD schema, its value is free-form, or it is not among the fields an operator is documented to set.
2. **What each carries.** The kubelet subset carries the fields behind serving certificates, graceful shutdown, swap, eviction, reserved resources, CPU, memory and topology management, pod limits, feature gates, unsafe sysctls, container log rotation, image garbage collection, taints at registration, the cluster domain, image pull settings, user namespaces and tracing. The kube-proxy subset carries the metrics bind address, node port addresses, the cluster CIDR, local traffic detection, the iptables, IPVS and nftables blocks, conntrack, feature gates and the OOM score adjustment. It omits the bind address and the healthz bind address, and `mode`: the upstream type documents `mode` as the field that selects the proxy mode, and Ichor does not carry it. So the IPVS and nftables blocks are carried with no field in the subset that selects them. This ADR does not establish whether a block has any effect without `mode`. The scheduler subset carries `profiles` with their `plugins`, and `percentageOfNodesToScore`.
3. **Not carried, on purpose.** The kubelet fields Talos protects (`authentication`, `authorization`, `cgroupRoot`, `kubeletCgroups`, `systemCgroups`, `port`, `protectKernelDefaults`, `resolvConf`, `rotateCertificates`, `staticPodPath`, `seccompDefault`): a field Talos refuses is worse than a field left out, and a CRD field cannot be withdrawn. The floating point and quantity fields: `memoryThrottlingFactor` and `logging` of the kubelet, `clientConnection` and `logging` of kube-proxy, `leaderElection` and `clientConnection` of the scheduler, and the scheduler's `extenders`. The scheduler's `profiles[].pluginConfig`, whose arguments are a free-form object: scoring strategy tuning and any other plugin argument is therefore not expressible. Every other omitted field is in the table with its reason.
4. **Typed fields Ichor owns.** The `image` of each of the three documents follows `spec.kubernetesVersion` and is set by the Kubernetes upgrade. `enabled` of kube-proxy belongs to `spec.cni.kubeProxy`. `enabled` of kube-scheduler is part of the control plane's shape, which Ichor owns, and a config patch may not switch it off. Neither is in the CRD, and a Talos document that sets one is refused with the field and the owner named.
5. **An omitted field is refused, not trimmed.** Reading a Talos document into the typed form fails on any field the subset does not carry, naming it, at any depth. In the cluster, the API server removes a field its schema does not have from the stored object unless the client asks for strict field validation, which `kubectl` does by default: such a client is refused with the path of the field. A client that does not is not told. That gap belongs to the API server, not to the webhook, which only sees the object after the field has gone.
6. **Fields keep their upstream type, with two exceptions.** A field whose upstream type is a struct value becomes a pointer, so that an unset duration or block is left out of the rendered document instead of written as a zero value. List type and map key markers are not copied: the scheduler's profiles are keyed by a name with no default, which a CRD refuses, so lists are atomic. Schema markers that validate a value are copied.
7. **Fields are added by deleting an omit row.** The set is append-only like every CRD field: a field carried cannot be taken back, so a doubtful field stays omitted until someone needs it. The fields the subsets carry are listed in `pkg/typedconfig/testdata/carried_fields.txt`, outside the generator, because a row added to an omit table removes the field from the mirror and from everything derived from the table in the same step; a test fails when a listed field leaves the mirror, and withdrawing one on purpose means removing its line.
8. **`KubeAuthenticationConfig` is Ichor-owned.** Ichor renders this document itself (ADR 0094), and Talos merges it by replacing its `configuration`. A patch carrying it would replace Ichor's issuers and drop the cluster's own sign-in. Its classification said a patch was merged over a baseline, which is not true of a replacing field.
9. **`KubeAdmissionControlConfig` is unstructured.** Its payload is one free-form configuration per admission plugin, so no single schema exists, and Ichor already writes the Pod Security plugin itself. What a patch cannot express there (Pod Security exemptions and versions other than the latest) belongs on `spec.security.podSecurity`.
10. **`KubeStaticPodConfig` ships, carrying its pod as the core v1 `Pod` without `status`, and its CRDs are applied with server-side apply.** Talos types the pod as an untyped object and documents it as a static pod definition: the `apiVersion`, `kind`, `metadata` and `spec` of a Kubernetes Pod. The mirror is the core v1 `Pod` with its `status` omitted (`podOmits`). The status is what the kubelet reports about a running pod; an author does not write it into a static pod definition, so a document that sets it is refused with the field named. `apiVersion` and `kind` are carried, unlike the kubelet subsets, where Talos sets them. `metadata` is carried as the core `ObjectMeta` and `spec` as the core `PodSpec`, since a static pod needs a security context, host networking, host path volumes and capabilities. The mirror's Go field is `Pod`, and its YAML name is `pod`. The pod schema is 302,271 bytes of compact JSON in `TalosConfigPatch`, 832 bytes more than the `PodSpec` it replaces. The two CRDs that embed the union are 504,967 bytes (`TalosCluster`) and 472,816 bytes (`TalosConfigPatch`) as compact JSON: the output of `yq -o=json -I=0` on each file in `config/crd/bases/`, without its final newline. Client-side apply, as `kubectl apply` does without `--server-side`, writes the whole object into the `kubectl.kubernetes.io/last-applied-configuration` annotation, which the API server limits to 262,144 bytes, so it refuses both CRDs. Server-side apply writes no such annotation. `make install` and `make deploy` therefore pass `--server-side`, and the installer and `ichor init` already apply server-side. The chart is installed by Helm. Helm 4, the version `install-helm` fetches, applies server-side by default. Helm 3 patches a release from the manifest it stored, not from an annotation, so it installs these CRDs too. Helm keeps each release in a Secret that holds the rendered manifest and the chart's files, so the two CRDs are stored twice. The gzipped, base64-encoded release record that Helm writes to the Secret's `data.release` is 991,296 bytes, 57,280 bytes under the 1 MiB (1,048,576-byte) limit; before this change the same chart gave 971,752 bytes. These are the output of Helm's own release encoder at the pinned v3.21.4 (`encodeRelease` in `pkg/storage/driver/util.go`: JSON, gzip at `BestCompression`, base64), applied to the release that the Helm SDK's client-only dry-run install produces from `dist/chart` at Kubernetes v1.36.0. The release's status is set to deployed, its description to "Install complete", and its first and last deployed times to 2026-01-01T00:00:00Z, so the figure is the same on every run; the same method gives 971,752 for the chart at 0008eb30c. They are measured from the chart, not read from a cluster, and they do not include the Secret's own metadata. Moving the CRDs to `crds/` would store the rendered CRD YAML once, in the chart's files, with no copy in the manifest; the CRDs stay in `templates/` because Helm 3 never applies `crds/` content on `helm upgrade`. A patch whose pod is large can still exceed the limit when a person applies it client-side, since it is the object itself that is annotated; an ordinary static pod is far smaller. The accepted count and the shipped count are both 65.
11. **Two Kubernetes configuration modules become direct dependencies**, `k8s.io/kube-proxy` and `k8s.io/kube-scheduler`, alongside `k8s.io/kubelet`, at the Kubernetes version Ichor already builds against. Only their types are used, to name the fields of the subsets.

## Rejected

- Mirroring the whole upstream type: five of the six cannot be written as a schema, and the sixth is too large.
- A raw object for the fields a schema cannot express: it is the free-form escape hatch the typed-only rule forbids.
- Dropping an omitted field quietly, for a field that is not a credential: an operator would see a kind that appears to support a setting that does nothing. The credential fields are dropped on purpose, through the secret table, and the generator reports each one (ADRs 0012, 0149 and 0157 decide the four volume kinds and the external manifest kind this way).
- Shipping a field Talos itself refuses.

## Consequences

An operator who needs a setting outside a subset cannot set it through these kinds until its omit row is deleted and a release carries it; the omit tables are the list. Plugin arguments of the scheduler stay unreachable. `TalosCluster` embeds the union, so each subset is paid twice in CRD size; the scheduler's `plugins` block is the largest part of that.

## Amendment (2026-11-16): the fields nobody had asked for are carried

Decided by the maintainer, with ADR 0165: the three subsets carry every field of the upstream configuration that a CRD schema can express and Talos accepts. Of the 86 rows of the omit tables whose reason was that no documentation has an operator set the field (71 of the kubelet's, 10 of kube-proxy's, 5 of the scheduler's), 85 are deleted, and their paths are appended to `pkg/typedconfig/testdata/carried_fields.txt`. Decision 7's "a doubtful field stays omitted until someone needs it" no longer holds: `spec.config` is the one place to write every setting, and a subset of it would be a setting that cannot be written there. What stays out is what the reasons say: the fields Talos protects, the types a CRD schema cannot express, the free-form `pluginConfig`, the pod's status, and the scheduler's embedded `DebuggingConfiguration`, the 86th of those rows, which a subset does not flatten: it is not a field of its own, and its row now says so. The patches CRD grows by 3,108 bytes of the Helm release record, which is 578,416 of the 1,048,576 allowed with `documents[]` gone.
